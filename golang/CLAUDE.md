# Thor PSA Validator (Go)

This workspace uses the Thor MCP server (Go binary) to validate AWS partner
competency applications.

## What Thor does
- Validates partner submissions (Excel checklists + PDFs) against control
  requirements using Bedrock Claude
- Produces PASS / FAIL / WAIVED verdicts with reasoning for each control
- Supports parallel validation, consensus mode, diff between runs, and
  HTML export

## MCP tools available
`thor_doctor`, `thor_convert`, `thor_validate`, `thor_diff`, `thor_prep`,
`thor_list_controls`, `thor_export`, `thor_map`

> **Note:** the Python build also offered a `thor_run` tool for end-to-end
> ticket-driven workflows. The Go build does not — assemble partner folders
> manually and call `thor_validate` directly.

## Partner folder structure
```
PartnerName/
├── checklist.xlsx           # Excel checklist (root level)
├── partner_responses.csv    # Generated by thor_convert
├── evidence_map.json        # Generated by thor_map (or auto by thor_validate)
├── supporting_docs/         # PDFs, architecture diagrams, screenshots
├── validation_summary.md    # Latest validation results
├── validation_progress.log  # Live progress during validation
└── reports/                 # Run manifests + timestamped summaries
    ├── run_<ts>.json        # Auditable per-run manifest (Go binary)
    └── summary/             # Timestamped archived reports
```

## Key concepts
- **Designation categories** filter which controls apply (e.g.,
  "Generative AI Applications" excludes FM-training controls)
- **Application type** (SERVICE vs SOFTWARE) determines control suffixes
- **Evidence map** is a control→files mapping built by a Bedrock pre-pass.
  `thor_validate` builds it automatically the first time a partner folder
  is validated and reuses it on subsequent runs (regenerated when files
  under `supporting_docs/` change). The map keeps each per-control
  Bedrock call under the 100-page-per-request cap and dramatically reduces
  noise. Run `thor_map` explicitly to inspect/regenerate. Pass `--no-map`
  to fall back to "send every file to every control"
- **Credentials** resolve via the AWS SDK default chain — env vars, named
  profile (`AWS_PROFILE`), `credential_process` profiles, and the standard
  shared-config file. No hardcoded keys
- **Consensus mode** runs each control N times and uses majority vote for
  borderline cases. The Python early-stop semantics (skip run 3 when all
  controls passed runs 1 + 2) is preserved

## Credential refresh
If you see expired-credential errors, tell the user to refresh and retry —
no server restart needed. Pick whichever applies:

```
aws sso login --profile <profile>     # SSO users
aws configure                         # static keys
isengardcli assume <account>          # Amazon Cloud Desktop
ada credentials update                # alternative for Cloud Desktop
```

## Versus the Python build
The Go binary starts instantly (no venv). All seven Python tools that ship
in the Go build behave the same. The `partner_responses.csv` and
`validation_summary.md` formats are byte-equivalent so existing partner
folders continue to work.
