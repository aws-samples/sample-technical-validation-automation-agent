# Technical Validation Automation Agent

This workspace uses the Thor MCP server (`thor-mcp`) to validate AWS
partner competency applications for [Partner Program Validation](https://aws.amazon.com/partners/programs/specializations/).

## IMPORTANT: Always run `thor_doctor` first

Before ANY validation, ALWAYS call `thor_doctor` to verify credentials
and Bedrock access are working. If it fails, guide the user through
credential setup before proceeding. Do NOT attempt validation without
a passing doctor check.

## What this tool does
- Validates partner submissions (Excel checklists + supporting docs)
  against the program control catalog using Amazon Bedrock (Claude)
- Produces PASS / FAIL / WAIVED verdicts with reasoning for every control
- Supports parallel validation, consensus mode, run-to-run diff, and
  self-contained HTML export

## MCP tools available
`thor_doctor`, `thor_convert`, `thor_map`, `thor_validate`, `thor_diff`,
`thor_prep`, `thor_list_controls`, `thor_export`.

## Partner folder structure
```
PartnerName/
├── checklist.xlsx           # Excel checklist (root level)
├── partner_responses.csv    # Generated by thor_convert
├── evidence_map.json        # Generated by thor_map (or auto by thor_validate)
├── supporting_docs/         # PDFs, architecture diagrams, screenshots
├── validation_summary.md    # Latest validation results
├── validation_progress.log  # Live progress during validation
└── reports/                 # Run manifests + timestamped summaries
    ├── run_<ts>.json        # Auditable per-run manifest
    └── summary/             # Timestamped archived reports
```

## Key concepts
- **Designation categories** filter which controls apply (for example,
  *Generative AI Applications* excludes FM-training-specific controls).
- **Application type** (`SERVICE` vs `SOFTWARE`) determines the suffix
  applied to certain control IDs.
- **Evidence map** is a control→files mapping built by a Bedrock
  pre-pass. `thor_validate` builds it automatically the first time a
  partner folder is validated and reuses it on subsequent runs
  (regenerated when files under `supporting_docs/` change). The map
  keeps each per-control Bedrock call under the 5-document-block /
  100-page-per-request limits and dramatically reduces noise. Run
  `thor_map` explicitly to inspect or regenerate it; pass `no_map: true`
  to fall back to "send every file to every control".
- **Credentials** resolve via the AWS SDK default chain — env vars,
  named profile (`AWS_PROFILE`), `credential_process` profiles, and the
  shared-config file. No hardcoded keys.
- **Consensus mode** runs each control N times and majority-votes
  borderline verdicts. When `consensus = 3` and every control passed
  runs 1 and 2, run 3 is skipped.

## Credential refresh

**Kiro users:** Credentials are in the `env` block of
`~/.kiro/settings/mcp.json`. When expired, update the `AWS_ACCESS_KEY_ID`,
`AWS_SECRET_ACCESS_KEY`, and `AWS_SESSION_TOKEN` values and save.
Kiro reconnects automatically.

**Claude Code / Cursor users:** Refresh credentials in your shell:

```
aws sso login --profile <profile>     # SSO users
aws configure                         # static keys
```

No server restart needed in either case.
